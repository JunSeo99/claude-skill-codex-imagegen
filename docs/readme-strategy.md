# Repository presentation strategy

Patterns were taken from widely used skill repositories, inspected on 2026-09-09: explain a complete user workflow before implementation details; keep skill folders self-contained with explicit installation; show the result early with a copyable install command and concrete requests; give a clear capability table and the exact install directory.

## Applied

Position around an outcome: make and refine images in Claude Code while coding continues. Put installation and a real generation/edit sequence above architecture. Distinguish the differentiators that are actually implemented: subscription-only execution, background workers, restrained interviews, separate directions, preserved originals, alpha verification, and concise relay context.

Keep proof inspectable through prompts, tests, dated observations, a CI badge, a reproducible archive, and release notes. Maintain Korean, Japanese, and Simplified Chinese entrypoints. Use focused GitHub topics and a plain repository description so both people and agents can find the project. A single star invitation follows the useful content.

Do not copy competitor language, manufacture testimonials, advertise unsupported model selection, make total-token claims from character counts, or add fake popularity badges. No unsolicited promotional messages or issues are posted. Future adoption should be evaluated from real installs, issues, repeat usage, and stars; this release does not promise a star count.
